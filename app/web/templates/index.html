PL/SQL (Oracle) vs Transact-SQL (SQL Server)

          

            This analyzer targets Oracle's dialect — PL/SQL and Oracle SQL. If you're coming from SQL Server,
            most of the surface-level syntax looks familiar but a lot of the details differ: block structure,
            variable declaration, string concatenation, exception handling, and especially how stored code and
            dynamic SQL are written. This page is a quick-reference bridge between the two, focused on the parts
            most likely to trip someone up while writing or reading SQL this tool analyzes.

Analyze first. Simulate second. Execute last.

          
This is a local, offline-first preflight layer for Oracle SQL. It never executes SQL and never sends SQL anywhere — it parses statements with SQLGlot's Oracle dialect and applies a deterministic rule engine.

          
Findings are conservative by design: the engine distinguishes PROVEN, POSSIBLE, and UNKNOWN, and it never manufactures a database fact (like a row count) while offline.

          
PL/SQL blocks, stored procedures, dynamic SQL and multi-statement scripts are now recognized (see the Rule Catalog's PLSQL category). Oracle DEV/TEST connectivity, impact simulation, and execution plans are planned in later versions — see scope.md.
